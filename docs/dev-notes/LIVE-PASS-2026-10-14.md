# Live pass: v1.6.9 on EasyEDA Pro 3.2.206, 2026-10-14

Write-path checks for the 0.4.26 update (v1.6.6 to v1.6.9, never published
until 1.6.9), run on a scratch two-layer project with an empty board. Every
primitive the pass created was deleted again afterwards.

## Verified working

| Check | Result |
|---|---|
| `pcb_create_pad` | SMD `['ELLIPSE',60,60]` on layer 1, THT `['ELLIPSE',80,80]` with `['ROUND',35]` plated on layer 12, and `['RECT',60,40,10]` all stored as asked |
| Region rule names | `["no_components","no_wires"]` stored as `[2,5]`; modify to `["no_pours","no_fills"]` stored as `[7,6]` (`prohibitType` COPPER, FILL in the source) |
| Via type name | `through` stored as `viaType` 0 (NORMAL) |
| Unknown enum name | refused before EasyEDA with a one-line message (1.6.9) |
| Rule config | `save` (bare and `{config,name}`), `get_by_name`, `delete`, `overwrite_current` all work; a hand-built config and `{Spacing:{}}` (1.6.9) are refused |
| Pipe-format round trip | `document_save_to_file` then `document_load_from_file` with strict validation on a PCB: 142/142 lines pass, board reads back unchanged (1.6.9) |

## EasyEDA behaviour found

- **Fills and regions drop values, and the reply hides it.** Create and
  modify resolve with the values sent. What EasyEDA stores: every fill solid
  with a 0.2 outline, whatever `fillMode` and `lineWidth` say; regions keep
  their rule types but not `regionName` (stored as "PROHIBIT") or
  `lineWidth`. Since 1.6.9 the fill and region handlers re-read the
  primitive and return `notApplied` for values that did not stick.
- **Pour rebuild through the API does not work on 3.2.206.** In the runtime
  API bundle (`pro-api/0.3.50`), `IPCB_PrimitivePour.rebuildCopperRegion()`
  sends the RPC `PCB_PrimitivePour.rebuildCopperRegion` with
  `{ids:[id], isLast:false}`, gets `undefined` back for an API-created pour,
  and its helper reads `.length` of that: `TypeError: Cannot read
  properties of undefined (reading 'length')`. Adding a board outline or a
  pour priority does not change it. `rebuildCopperRegions` (the collection
  call in the 0.4.26 types) is not in the runtime, and no other RPC
  rebuilds pours or runs a UI command. `pcb_rebuild_pours` now says to
  rebuild all copper in the editor (Shift+B). Not yet tested: a pour drawn
  by hand in the editor.
- **Live documents use a new line format.** `getDocumentSource` (so
  `document_save_to_file`, and every backup snapshot since August) returns
  `{header}||{body}|` lines for both schematics and PCBs; only
  `project_export_file` still writes the JSON arrays the per-tag schemas and
  `src/lib` describe. The old validator therefore reported every line
  invalid, and the strict upload default refused every such source. 1.6.9
  checks these sources by structure (all 13,160 lines of the real documents
  in the backup repo pass) and the reader and symbol editor refuse them
  instead of reading an empty model.
- `overwrite_current` renames the board's rule set to "自定义配置" (custom
  configuration) and adds it to the user's saved list. The editor keeps
  showing that name until the document is reopened, even after the source
  names the original set again.
- One `save` on a profile with no user configs returned `true` but stored
  nothing; every later save stored. Not reproduced.
- Rule-config `get_by_name` on a missing name and `get_default_name` resolve
  with nothing; tools now report `null` instead of an invalid MCP result.

## Not covered

Gerber export, footprint source reads and schematic image export were
covered (and the last two pulled) in the read-only pass earlier the same day.
The hand-drawn pour rebuild and the 3.2.206 re-tests of older workarounds
(API via joined to a track, phantom "disconnected" DRC, `project_import_file`
into an existing project) remain open.
